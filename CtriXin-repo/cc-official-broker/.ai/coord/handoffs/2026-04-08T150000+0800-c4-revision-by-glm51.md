## What Changed

Three paths in `POST /sessions` now truly fail-fast when `bindingResult.runtime === null`:

1. **Direct-connect** (stubServer ~line 1680): Returns HTTP 503 with `{ error: "runtime_binding_failed", reason }` instead of creating session.

2. **Standard create**: Same — returns 503, no session created.

3. **Standard resume**: Same — returns 503, old session not overwritten, old `remoteService` not preserved as-if success.

Failure responses distinguish two reason codes:
- `no_healthy_runtime_available` — pool has no healthy runtimes for new session
- `bound_runtime_not_acceptable` — existing binding points to unhealthy/disabled runtime
